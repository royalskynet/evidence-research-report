# Evidence Research Report

以最小足够研究回答决策问题。证据质量优先于来源数量；无法核实就排除，不以更多搜索掩饰资料缺口。

## 先路由深度

| 模式 | 适用情况 | 默认预算 |
|---|---|---|
| 不调研 | 只排版、翻译或整理已核实内容 | 不搜索、不开页、不新增主张 |
| 快速 | 一个窄问题、短报告或单点事实确认 | 最多 2 个搜索批次；通常读取 2–4 个最强页面 |
| 标准 | 供应商尽调、2–5 个对象比较、正式决策报告 | 先做 2–3 个搜索批次；通常保留 6–12 个有效来源；只为具名缺口追加 |
| 深度 | 用户明确要求详尽／完整研究，或同意高影响跨司法管辖区升级 | 读取 `references/deep-mode.md`；先说明范围与预算 |

高风险不等于一律深度。单点法律或监管问题可用快速或标准模式，直接查现行法律／监管原文。除非用户已明确要求，禁止自动升级深度模式。

## 核心证据规则

1. 网络搜索只发现候选来源；引用前必须打开结果或 URL，读取实际页面。
2. 搜索摘要、标题、AI 摘要及无法读取的页面不能支撑正文。
3. 公司官网只能直接证明其自述；成效、争议、行业领先与持续合作需要相符的独立或原始证据。
4. 法律、监管、法院、政府登记与正式申报主张优先使用对应原文。
5. 重要事实、数字、政策、合作、事件与评级后放 `[N]`；同一 URL 固定同一编号。
6. 无法核实的内容从正文删除；重要缺口写成“本次已查阅的公开来源未能确认……”，不得写成不存在。
7. 推论标示 `[推论]`，并紧邻列出已引用的事实依据。
8. 不设置来源配额，不为正反平衡生造论据，不使用无量尺的星级或数字评分。

快速模式遵守以上规则即可。标准模式开始前完整读取 `references/evidence-policy.md`；撰写正式报告时读取 `references/report-patterns.md`。

## 执行流程

1. 从用户请求提取决策问题、范围、资料截至时间、语言与篇幅。只有缺失会实质改变结果时才提一个澄清问题。
2. 列出最多 3–5 个必答问题。标准与深度模式：先列 2–3 个利益相关视角（如采购方、监管、竞品），每个视角至少覆盖一问，避免漏掉某方真正在意的面向；快速模式通常只有 1–2 个。
3. 用少量中英文查询找原始来源；平台支持时把互不依赖的查询合并在同一工具调用，避免同义词反复搜索。搜尋或抓取被封鎖時，读取 `references/retrieval-resilience.md` 并改用 `scripts/search_web.py`／`scripts/fetch_page.py` 的退路链，不得直接放弃改写缺口。
4. 优先打开最可能直接回答问题的页面。页面只重复已知内容时，不继续扩张。
5. 每读完一轮，检查“还缺哪个会改变结论的重要证据？”没有具名缺口就停止。
6. 依所选模式撰写简体中文 Markdown；公司名、产品名与技术术语保留原文。用户明确指定其他语言时以用户要求为准。
7. 定稿前先筛出最重要、最影响决策的主张（consequential claims）优先核，再逐项核对所有重要主张与其来源语义是否相符；不是随机抽查。

立即停止搜索的条件：

- 必答问题均已有足以支持的来源；
- 连续两次搜索没有新增重要证据；
- 已达模式上限。达到上限时列明资料缺口，不默认升级。

快速与标准模式不使用子代理或外部模型做引用核对。深度模式只有存在互不依赖的研究轴线时才可用子代理。

## 输出与验证

- 默认交付纯文字与 Markdown 表格，不建立 DOCX／PDF。
- 不加作者、部门或日期署名，除非用户要求。
- 章节随内容调整，不保留空章，不重复结论。
- 参考资料列出：序号、来源／标题、日期（如有）、查阅日期、完整 URL。
- 报告若已存成 Markdown，从本技能目录执行 `python3 scripts/validate_report.py <report.md>`；必要时先把脚本路径解析为绝对路径。

修正所有 `FAIL` 后才交付。`PASS` 只证明编号、URL 与禁用标记通过机械检查；仍须完成逐项语义核实。

可选加固（均为可选，不影响 PASS 判定）：
- `--check-list`：输出「主张→来源」逐项核对清单（机器抽取、人工判定），定稿前据此逐项核对语义；
- `--check-urls`：HEAD 探测引用链接存活，离线环境自动跳过；
- 深度模式用 `--ledger ledger.yaml` 交叉检查来源／主张台帐与正文引用是否一致。

## 安全与边界

- 不读取 shell 启动文件或 API key，不把报告内容、主张清单或 API key 传给任何第三方模型或服务。
- 允许把目标 URL／搜索 query 交给白名单服务（Firecrawl、r.jina.ai、web.archive.org、archive.today）取得页面内容；本地渲染层（Camoufox）不把 URL 外送。
- 不因技能存在而改写用户明确要求保留的内容。
- 若用户只要排版，完全停用研究流程。
- 若来源受登录、付费墙或封锁限制，读取 `references/retrieval-resilience.md` 并改用检索退路；确实找不到就保留缺口。
