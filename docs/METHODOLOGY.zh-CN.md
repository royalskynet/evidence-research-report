# 方法说明

## 设计目标

本技能按以下顺序优化四项指标：

1. 每个重要主张都能追溯到实际打开并阅读过的来源。
2. 证据类型适合所支持的主张。
3. 研究成本与决策规模相称。
4. 最终报告足够精炼，可以直接使用。

## 来源等级

| 等级 | 典型来源 | 适合证明 |
|---|---|---|
| S0 | 现行法律、监管机构、法院、公共登记、正式申报、原始数据 | 法律要求、登记、裁判与申报事实 |
| S1 | 公司网站、产品/API 文档、公告、状态页与安全文件 | 组织公开发布或自述的内容 |
| S2 | 合作方公告、具有编采责任的媒体、采购记录 | 独立报道的事件或合作方立场 |
| S3 | 公开方法的研究、学术或行业分析 | 在指定样本、日期与方法范围内的结论 |
| S4 | 论坛、社交媒体、聚合页、搜索摘要 | 只能作为进一步调查的线索 |

“官方优先”取决于主张类型。产品手册是已记录功能的原始证据；监管机构或法律原文是法律义务的原始证据。第一方营销材料不能单独证明实际成效或行业领先。

## 主张规则

- 引用前必须打开并阅读来源。
- 核对主语、范围、日期与限定语，而不只是关键词相似。
- 将分析标记为 `[推论]` 或用户指定语言的等价标记，并在附近引用事实依据。
- 重大或有争议的主张优先取得两个独立来源；一份权威 S0 文件已直接解决问题时无需凑数。
- 使用“在本次查阅的公开来源中未找到”，而不是声称某事不存在。
- 区分指控、调查、裁判、和解、制裁等不同程序状态。

## 成本控制

研究开始时最多列出三到五个决策问题。平台允许时，把互不依赖的查询合并为同一搜索批次。每轮结束后，只能为一个会改变结论的具名证据缺口继续搜索；如果没有，就停止。

自动停止条件为：

- 所有决策问题已有足够支持；
- 连续两次搜索没有新增重要证据；或
- 达到所选模式声明的上限。

达到上限后应写明证据缺口，不得自动升级任务。

## 交付闸门

交付前，智能体必须逐项核对重要主张与引用、明确处理来源冲突、删除无支持内容，并运行确定性验证器。验证器刻意保持窄范围和本地运行：它不会抓取 URL，也不会判断语义是否一致。
