# 使用说明

## 调用方式

需要确定性路由时，可明确点名技能：

```text
使用 evidence-research-report 的快速模式，确认供应商 A 的文档是否说明功能 X。
```

当请求明确属于来源核实、尽调、比较、监管研究或决策支持时，Codex 版也可以被隐式调用。

## 选择模式

- **不调研：**只排版、翻译或重整已经核实的材料；不搜索，不新增主张。
- **快速：**一到两个决策问题、窄范围事实确认或短回答。
- **标准：**正式尽调，或比较两到五个对象。
- **深度：**仅在用户明确要求详尽研究，或同意重要的跨司法管辖区升级时使用。

高风险不等于必须使用深度模式。若现行法律原文能直接回答，一个窄范围法律问题仍可使用快速或标准模式。

## 如何写好请求

在会影响结果时，写明决策问题、研究对象、资料截至时间、输出语言与篇幅：

```text
以 2026-06-30 为资料截止日，比较供应商 A 与 B 已公开的筛查覆盖范围和限制。使用标准模式、简体中文，不超过 1,200 字。
```

技能最多只提出一个澄清问题，而且仅限缺失信息会实质改变结果的情况。

## 预期输出

- 结论先行
- 研究范围与资料截止日
- 带编号引用的已验证事实
- 必要时明确标记的推论
- 会影响决策的资料缺口
- 含完整 URL 的参考资料表

报告结构应与问题规模相称，不保留空的固定章节。

## 只排版边界

如果用户说明内容已经核实，并要求只排版，技能不得浏览、补充证据或修改主张。这能避免小型编辑任务被悄悄扩大成研究任务。

## 验证已保存报告

```bash
python3 scripts/validate_report.py report.md
```

交付前必须修复所有 `FAIL`。同时检查警告，并在适当时删除未使用的参考资料。
